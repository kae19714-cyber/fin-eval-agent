# Бизнес-требования к tool-у агента: `estimate_effect`

Пример требований, по которым прототип аналитика передаётся в промышленную разработку на внутренней платформе. Методика описана в [METHODOLOGY.md](METHODOLOGY.md), эталонная реализация — `fineval/tools/effect.py`.

## 1. Назначение

Агент финансовой оценки вызывает инструмент, чтобы получить **фактический инкрементальный эффект** пилота бизнес-инициативы на чистый доход банка. Эффект нужен с оценкой неопределённости, достаточной для расчёта NPV и вероятности окупаемости.

**Пользователи результата:** агент (машиночитаемый JSON), аналитик дирекции, инвестиционный комитет (через отчёт).

## 2. Контракт

**Вход** (валидируется до запуска; лишние поля запрещены):

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `metrics` | list[enum] | нет | Метрики из справочника: `net_income`, `interchange_income`, `nii_income`, `net_cashback_cost`, `spend`, `avg_balance`, `is_active`. По умолчанию — `net_income` и компоненты |
| `by_segment` | bool | нет | Дополнительно — эффект на `net_income` по сегментам |

**Предусловия:**
- витрина собрана (`build_data_mart`);
- статус качества данных не `error`, иначе отказ с понятным сообщением.

**Выход:**

| Поле | Описание |
|---|---|
| `effects.<metric>.itt` | эффект на клиента пилотного региона в месяц |
| `effects.<metric>.se`, `ci95`, `p_value` | неопределённость; ошибки кластеризованы по региону |
| `effects.<metric>.counterfactual_mean`, `relative_effect` | эффект относительно контрфакта |
| `take_up` | доля подключивших в пилоте |
| `att_per_adopter_month` | эффект на подключившего (ITT / take_up) с ДИ |
| `by_segment` | при запросе |
| `warnings[]` | непройденная проверка трендов, мало кластеров и т.п. |

**Ошибки** возвращаются агенту как `is_error=true` с текстом на русском, по которому модель может исправить вызов: невалидные параметры, не выполнены предусловия, критичные ошибки качества данных.

## 3. Источники и витрина

- **Сырые таблицы:** `regions`, `clients`, `card_activity`, `balances`, `cashback`.
- **Витрина:** `sql/mart_client_month.sql`, один SQL для DuckDB и Spark SQL. Гранулярность — клиент × месяц.
- **Обязательные проверки качества:**
  - уникальность `client_id × month`;
  - ссылочная целостность;
  - отсутствие пропусков и отрицательных сумм;
  - `category_spend ≤ spend`;
  - контаминация контроля (подключения вне пилота) — предупреждение.

## 4. Алгоритм

1. Within-преобразование (вычитание средних) по клиенту и месяцу (alternating projections; работает и для несбалансированной панели).
2. МНК `y ~ treated_post` на преобразованных данных.
3. Кластерная ковариация CR1 по `region_id`, ДИ по t(G−1).
4. ATT = ITT / take_up.
5. Сегментный разрез — тот же расчёт на подвыборках.

## 5. Нефункциональные требования

| Требование | Значение |
|---|---|
| Объём | до 10 млн клиентов × 36 мес. (Spark; within-преобразование через groupBy/join) |
| Время ответа агенту | ≤ 5 мин на полном объёме; ≤ 10 с на демо-объёме |
| Детерминированность | одинаковый вход → одинаковый выход (без случайности) |
| Журналирование | вход, выход, длительность каждого вызова (`runs/<id>/trace.jsonl`) |
| Версионирование | версия методики и SQL в выходе (план: поле `method_version`) |

## 6. Критерии приёмки

Приёмка проводится на синтетических данных с известным истинным эффектом (`fineval/data_gen.py`). Автотесты — `tests/test_acceptance.py`.

| # | Критерий | Тест |
|---|---|---|
| 1 | Витрина не теряет и не размножает строки, `net_income` пересчитывается из компонентов | `test_mart_row_count_and_formula` |
| 2 | SQL переносим (нет диалектных функций DuckDB) | `test_sql_is_portable` |
| 3 | 95% ДИ накрывает истинный эффект на демо-данных | `test_did_recovers_true_effect` |
| 4 | Калибровка: покрытие ≥ 8/10 и ложные тревоги теста трендов ≤ 2/10 на 10 независимых пилотах | `test_method_calibration_over_seeds` |
| 5 | Нарушение параллельности ловится и попадает в `warnings` | `test_pretrend_violation_detected` |
| 6 | Невалидный вход и невыполненные предусловия дают понятную ошибку, а не исключение | `test_registry_rejects_bad_input`, `test_prerequisites_enforced` |
| 7 | Spark-витрина совпадает с DuckDB по сумме `net_income` и числу строк | `tests/test_spark.py` |
